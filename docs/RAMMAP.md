# RAM map

Rebuilt in step 7.5. Since step 7.2 the whole ROM is source, so this map is
**complete** in the sense that matters: it lists every RAM address that any
instruction (or `dw`) in the game refers to, by name or by number, with how it is
used, which banks use it and which routines. It is generated by
`tools/rammap.py`, which reads the source the way rgbasm does (main.asm and its
includes, in order) and resolves names through `mmwr.sym`. The step-1.2 byte scan
(`tools/ramrefs.py`) could not tell code from graphics and is kept only for
history; see "Leads" below for what it got wrong.

```
586 RAM addresses referenced from code (4427 references)
  247 named (directly or as part of a named block), 339 without a name
  1 declared labels never referenced
```

Named addresses live in `ram/wram.asm`, `ram/hram.asm`, `ram/audio_ram.asm` and,
for a few, `def ... equ` constants. An address shown as `wName+N` sits inside a
named block. The rest have no label - deliberately: the project's rule is never
to guess a name (see CONVENTIONS.md), and a `wUnknown_XXXX` would only hide the
fact that nobody has looked. For those the table quotes what the source's own
comments say about the address, or failing that the region it lies in, and
names the routines that use it - which is usually enough to find out more.

Two kinds of reference the tally cannot see: fields reached by offset from a
base (object slots are `ld a,OFFSET / add a,c / ld l,a`; the audio track RAM is
indexed per track; many records are walked with `hl+`), and pointers built from
`HIGH()`/`LOW()` halves. That is why most of `ram/audio_ram.asm` and the object
slot fields do not appear below one by one; the object fields are in
`constants/objects.inc` and the step 5.x object files, the audio RAM in
`docs/AUDIO.md` §9.

## Leads

* **`$CD25` is not an address** (it led this list from step 1.2 to 7.4, "loaded
  into HL nine times"). Every hit was the byte pattern `21 25 CD` straddling two
  instructions: `call $2521` (`CD 21 25`) followed by another `call` (`CD`). No
  source line refers to `$CD25`. The `$CD25` open question in PLAN.md is closed.
* `$FFF2` (step 1.2) was the same kind of false positive: `ld hl,$FFF2` is -14.
* Unnamed addresses with the most uses are the best candidates for names in a
  later pass: `$FF92`/`$FF93`/`$FF94` and `$FFA2`/`$FFA3` (HRAM scratch with
  several meanings each - probably better left unnamed), `$CC00`-`$CC1B` (the
  spawn buffer; its fields are in `SpawnObject`'s comments), `$D80D`/`$D80E` and
  `$D811` (Mega Man's stage X and the screen's left edge).
* `wShotList` is declared but only ever reached by offset (`wShotListEnd` + n).
